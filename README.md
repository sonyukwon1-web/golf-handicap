# ⛳ 낙원 골프

멤버 4명(최진규 · 최문창 · 손유권 · 이지수)의 라운드 스코어를 기록하고,
실제 성적을 기준으로 핸디캡을 자동 산정하는 정적 웹앱입니다.
친구 모임용이라 명예의 전당 · 배지 · 벌칙 룰렛 같은 놀거리를 함께 넣었습니다.

서버가 없고 데이터는 브라우저 `localStorage`에 저장되며, JSON 파일로 내보내고
불러와서 멤버끼리 공유합니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # dist/ 로 정적 빌드
npm run preview  # 빌드 결과 미리보기
```

## 핸디캡 산정 규칙

1. 멤버별로 **최근 5경기의 그로스 평균**을 낸다. 5경기가 안 되면 있는 경기만으로 평균을 낸다.
2. 평균이 가장 낮은 멤버가 **기준(핸디 0)** 이 된다.
3. 나머지 멤버의 핸디 = `반올림(본인 평균 − 최저 평균)`.
4. 넷 스코어 = `그로스 − 핸디`. 라운드 상세에서는 넷 스코어 오름차순으로 순위를 매기며,
   동점은 공동 순위다.

새 라운드를 저장하면 위 계산이 전부 다시 돌아가므로 핸디는 항상 최신이다.

### 과거 라운드에 적용되는 핸디

각 라운드 상세에 찍히는 핸디는 **그 라운드까지의 기록으로 계산한 그 시점의 핸디**다.
지난 결과가 나중 라운드 때문에 뒤바뀌지 않고, 가장 최근 라운드의 핸디는 홈 화면의
현재 핸디와 항상 일치한다.

### 첫 라운드는 그로스로 겨룬다

기록이 한 번뿐이면 그 사람의 "평균"이 곧 그 날 타수라, 핸디가 타수 차이를 그대로
상쇄해 **전원이 동타**가 된다. 우승자도 꼴찌도 안 나오니 벌칙 룰렛도 못 돌린다.
그래서 라운드 순위에 쓰는 핸디는 **본인 기록이 2개 이상일 때부터** 적용한다.
첫 라운드는 그로스 그대로 겨루고, 두 번째 라운드부터 핸디가 붙는다.

(홈 화면에 보이는 현재 핸디는 규칙 그대로 최근 5경기 평균으로 계산한다.)

### 불참 처리

특정 라운드에 빠진 멤버는 타수를 비워두면 된다. 그 라운드의 순위와 평균 계산에서 모두 제외된다.

## 홀별 기록

라운드는 두 가지 방식으로 넣는다. **입력** 탭 위쪽에서 고른다.

- **홀별 기록** — 스코어카드 그대로 18홀을 적는다. 사진 인식도 이쪽으로 들어온다.
- **총 타수만** — 과거 기록을 여러 라운드 몰아 넣을 때 쓴다.

홀별 라운드에 담기는 것:

| 항목 | 설명 |
|---|---|
| 골프장 / 전반·후반 코스 | 예: 리앤리CC, Sky / Lake |
| 날짜 / 티오프 | 티오프는 선택 |
| PAR 18홀 | 각 홀 3·4·5 |
| 플레이어별 18홀 | **파 대비 오버 타수** (0 = 파, -1 = 버디) |

**총 타수는 직접 넣지 않는다.** PAR 합계 + 오버 합계로 자동 계산되고, 표 오른쪽 T 열과
아래 합계 줄에 실시간으로 나온다. 휴대폰 숫자 키패드에는 −가 없어서, 버디는 칸을 누른 뒤
표 위 **± 부호** 버튼으로 넣는다.

총 타수만 적힌 옛 라운드도 그대로 열린다 (`pars`/`holes`가 `null`이고 총 타수만 표시).

## 스코어카드 사진 인식 (OCR)

사진을 끌어다 놓거나 눌러서 고르면 [tesseract.js](https://tesseract.projectnaptha.com/)가
브라우저 안에서 읽는다. 사진은 기기 밖으로 나가지 않는다.
**여러 장을 한 번에** 올릴 수 있고, 한 장이 한 라운드다. 한 장을 저장하면 다음 장을 이어서 읽는다.

### OCR은 초안 작성 도구다

읽은 값은 **절대 바로 저장되지 않는다.** 항상 홀별 입력 표에 채워진 상태로 미리보기가 되고,
사용자가 셀 단위로 고친 뒤 "저장"을 눌러야 확정된다.

### 구조를 아는 파서

이 앱이 읽는 카드는 골프장 앱 캡처라 구조가 정해져 있다 — 상단에 골프장·날짜, 코스 이름 띠,
`HOLE(1~9, T) / PAR / 플레이어 4행` 표가 전반·후반 두 번. 셀 숫자는 파 대비 오버,
T 열만 그로스 총 타수다. 파서는 이 구조를 그대로 따라간다.

1. **두 번 읽는다.** 한 번은 한글+영문으로 이름·골프장·날짜를, 한 번은 **숫자만 허용**하고
   표 안 값을 읽는다. 숫자 칸에 한글 사전을 쓰지 않는 것이 정확도에 가장 크게 기여한다.
2. **글자 단위 좌표를 쓴다.** 실제 카드는 칸 간격이 좁아 `2 0` 이 `20` 처럼 한 단어로 읽힌다.
   단어가 아니라 글자마다 좌표를 받아, 글자 폭의 1.3배보다 벌어지면 다른 칸으로 나눈다
   (`36` → 한 칸, `3 | 6` → 두 칸).
3. **글자가 아니라 숫자 격자로 표를 찾는다.** `PAR` 이 `PAB` 로, 이름이 알아볼 수 없는 글자로
   읽히는 일이 잦아서, 글자를 기준으로 삼으면 표 전체를 놓친다. 숫자가 8칸 이상 늘어선 줄을
   표의 행으로 보고, 글자는 행에 이름표를 붙이는 데만 쓴다.
   블록의 기준선은 **`HOLE` 행의 `1 2 3 4 5 6 7 8 9`** 로 잡는다. 1부터 9까지 차례로 늘어선
   줄은 홀 번호 행밖에 없어서, `PAR` 이라는 글자보다 훨씬 뚜렷하다.
   후보를 세 가지(HOLE 행 다음 줄 → `PAR` 글자가 붙은 줄 → 값이 전부 3~6 인 줄) 두고
   **전반·후반 두 블록을 모두 찾아내는 쪽**을 고른다.
   `PAR` 글자만 믿으면 둘 중 하나만 읽혔을 때 나머지 나인을 통째로 잃고,
   값만 믿으면 플레이어 행이 우연히 전부 3~6 일 때 PAR 로 오인한다.
4. **이름 칸에서 새어 나온 숫자를 걷어낸다.** 열 간격 중앙값의 1.8배보다 멀리 떨어진 앞쪽 칸은
   표 밖으로 본다. (이걸 넣기 전에는 전반 9홀이 한 칸씩 밀렸다.)
5. **숫자가 없는 줄은 플레이어가 아니다.** 표 아래 "홀별 거리정보 보기" 버튼이 플레이어 행으로
   잡히던 문제를 이 규칙으로 막는다.
6. **머리글은 따로 읽는다.** 못 찾으면 위쪽 22%만 3배로 확대하고, 배경이 어두우면 흑백을
   뒤집어 한 번 더 읽는다. 골프장 이름은 **날짜 바로 윗줄**에서 가져오되, 큰 총타수가 같은 줄
   오른쪽에 붙어 있으므로 넓은 공백에서 잘라 앞부분만 쓴다 (`리앤리   104` → `리앤리`).
   티오프는 **날짜와 같은 줄**에서만 찾는다 (그러지 않으면 휴대폰 상태바 시계를 잡는다).
7. **코스 이름**은 `Sky-Lake` 처럼 한 줄에 적힌 표기를 먼저 보고, 없으면 표마다 붙은 띠에서
   가져온다 (Sky / Lake).

전처리는 확대 + 그레이스케일 + 히스토그램 양끝 2%를 잘라낸 대비 스트레치다.

### 검산

각 플레이어의 9홀마다 `PAR 합계 + 오버 합계 == T` 인지 확인한다.
어긋나면 미리보기와 입력 표에서 **그 행이 빨갛게** 표시되고 "인식 오류 가능성" 경고가 붙는다.

### 플레이어 지정

카드에는 이름이 `이**`, `최**`처럼 가려져 나온다. 최진규·최문창은 둘 다 `최**`라 자동 구분이
불가능하므로, 인식 후 각 행 옆 드롭다운에서 직접 고른다.

- 후보가 하나뿐인 행(카드 주인의 실명, 성이 겹치지 않는 `이**`·`손**`)은 자동으로 지정된다.
- 줄마다 **총타수를 크게** 보여준다. 최씨 두 명을 가르는 근거가 그 숫자이기 때문이다.
- 성이 겹치는 두 줄만 남았을 때 **한쪽을 고르면 나머지는 자동으로** 채워진다.

### 단계적으로 물러선다

한 번에 되지 않으면 설정을 바꿔 가며 다시 읽고, 가장 잘 읽힌 결과를 쓴다.

1. 2배 확대 + **흩어진 글자 찾기**(PSM 11). 격자는 직접 재구성하므로 레이아웃 분석이 필요 없고,
   상태바·제목·요약카드·버튼이 섞인 실제 캡처에 이쪽이 훨씬 안전하다.
2. 표를 못 찾으면 같은 크기에 **균일한 블록**(PSM 6)으로 재시도.
3. 그래도 안 되면 **원본 크기로 줄여** 재시도. 휴대폰에서 큰 이미지가 메모리에 걸려
   인식이 통째로 망가지는 경우를 여기서 건진다. 중간에 예외가 나도 다음 단계로 넘어간다.

전체 픽셀 수에 상한(1,400만)을 두어 지나치게 큰 캔버스를 만들지 않는다.

### 인식이 안 될 때

실패하면 무엇이 부족했는지 숫자로 보여준다 — 글자 수, 숫자 수, 줄 수, 격자 줄 수, PAR 행 수,
이름 후보 수, 플레이어 행 수, 사진 크기. 인식된 원문도 함께 펼쳐지고,
**“진단 정보 복사”** 버튼으로 이 전부를 한 번에 복사할 수 있다.

미리보기(아티팩트) 페이지는 외부 리소스를 막아 **사진 인식이 동작하지 않는다.** 그 경우
그렇게 안내한다. 배포한 사이트나 `npm run dev` 로컬에서 써야 한다.

## 재미 요소

### 명예의 전당 & 흑역사관 (랭킹 탭)

- **통산 우승 횟수** — 넷 스코어 1등. 동점이면 공동 우승으로 둘 다 센다.
- **통산 꼴찌 횟수** — 넷 스코어 최하위. 혼자 친 라운드에는 꼴찌가 없다.
- **개인 베스트 / 워스트** — 그로스 기준 최저·최고 타수.

### 배지

멤버 카드에 자동으로 붙는다.

| 배지 | 조건 |
|---|---|
| 🔥 N연승 중 | 본인이 나간 라운드 기준 연속 우승 2회 이상 |
| 💀 N경기 연속 꼴찌 | 연속 꼴찌 3회 이상 |
| 📈 최다 발전상 | 직전 5경기 평균 대비 최근 5경기 평균이 가장 많이 줄어든 사람 (1타 이상) |
| 🎯 안정왕 | 그로스 표준편차가 가장 작은 사람 (3라운드 이상) |

발전상을 "이번 달"이 아니라 최근 5경기로 잡은 이유는, 한 달에 한 번 치는 모임이라
이번 달 표본이 한 경기뿐이라 숫자가 튀기 때문이다.

### 라이벌 매치

두 명을 고르면 함께 친 라운드만 모아 넷 스코어로 승패를 센다.
최근 5번의 맞대결과 평균 그로스 차이도 같이 보여준다.

### 꼴찌 벌칙 룰렛

라운드를 **한 개** 저장하면 우승자 발표 화면이 confetti와 함께 뜨고,
"벌칙 정하기"를 누르면 룰렛이 돌아 그날 꼴찌의 벌칙을 뽑는다.
확정한 벌칙은 라운드 상세에 남는다.

**공동 꼴찌면 "꼴찌 결정전"을 먼저 돌린다.** 동점자만 올린 룰렛으로 한 명을 가린 뒤
그 사람에게 벌칙 룰렛을 돌린다.

기본 벌칙은 밥 사기 · 커피 사기 · 다음 라운드 캐디피 내기이고, 룰렛 안에서
바로 추가·삭제할 수 있다.

과거 스코어카드를 여러 장 몰아 넣을 때는 축포가 방해만 되므로 뜨지 않는다.

### 도발 멘트

홈 화면 맨 위에 상황을 보고 한 마디 얹는다. 연승 · 연속 꼴찌 · 핸디 받고도 꼴찌 ·
급성장 · 하락세 · 기준 멤버 · 최다 우승자 상황마다 문구가 여러 개 있고,
↻ 버튼으로 다른 멘트를 뽑는다. 이름 뒤 조사(이/가, 은/는)는 받침을 보고 고른다.

### 홀별 기록 통계

홀별 기록이 쌓이면 랭킹 탭에 추가로 나온다. 표본이 모자라면 억지로 순위를 만들지 않고 비워 둔다.

| 통계 | 기준 |
|---|---|
| 🎯 파3 킬러 | 파3 홀 평균 오버 최소 (파3을 4홀 이상 친 사람만) |
| 🚀 파5 킬러 | 파5 홀 평균 오버 최소 |
| 📉 후반 무너짐 | 후반 평균 오버 − 전반 평균 오버가 가장 큰 사람 |
| 🐦 버디 사냥꾼 | 버디 이상(오버 ≤ -1) 횟수 |
| 🍆 양파왕 | 파의 두 배 타수(오버 == 파) 횟수 |

### 시즌 랭킹

연도별로 순위 포인트를 쌓는다 — 1등 4점, 2등 3점, 3등 2점, 4등 1점.
지난 시즌은 "역대 시즌 챔피언"에 남는다.

### 동점 처리

넷 스코어가 같으면 **공동 순위**다 (공동 1위 다음은 3위). 통산 우승·꼴찌 횟수와 시즌
포인트도 모두 공동 순위 기준으로 센다 — 공동 1위 두 명은 둘 다 우승 1회, 둘 다 4점이다.

## 데이터 공유

- **내보내기** — 전체 기록을 `낙원골프_YYYY-MM-DD.json` 파일로 저장한다.
- **불러오기** — 받은 JSON 파일을 열면 현재 기록을 그 파일 내용으로 대체한다(덮어쓰기 전 확인창이 뜬다).

기록을 관리하는 사람이 라운드를 입력하고 파일을 단톡방에 올리는 식이 가장 단순하다.

## 배포

### GitHub Pages

저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 바꾸고 `main` 에 푸시하면
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) 이 알아서 빌드·배포한다.

### Vercel

저장소를 import 하면 Vite 프로젝트로 자동 인식된다. 수동 설정이 필요하면
빌드 명령 `npm run build`, 출력 디렉터리 `dist`.

`vite.config.js` 의 `base: './'` 덕분에 루트 도메인이든 `/<저장소이름>/` 하위 경로든
그대로 동작한다.

## 구조

```
src/
  lib/handicap.js      핸디캡·순위·추이 계산 (순수 함수)
  lib/storage.js       localStorage 저장, JSON 내보내기/불러오기, 입력값 정규화
  components/
    Dashboard.jsx      멤버 카드 + 차트 + 최근 라운드
    TrendChart.jsx     평균 타수 추이 라인 차트 (의존성 없는 SVG)
    RoundList.jsx      라운드 목록 · 넷 순위 상세 · 수정/삭제
    RoundForm.jsx      여러 라운드 연속 입력
    RoundFields.jsx    입력 필드 (신규·수정 공용)
    HoleRoundForm.jsx    홀별 한 라운드 입력 (OCR 진입점)
    HoleGrid.jsx         스코어카드 모양 18홀 입력 표
    ScorecardImport.jsx  사진 인식 · 플레이어 지정 · 검산 미리보기
    HallOfFame.jsx       명예의 전당 · 흑역사관 · 개인 기록
    SeasonRanking.jsx    시즌 포인트 랭킹, 역대 챔피언
    RivalMatch.jsx       1:1 상대전적
    WinnerCelebration.jsx  우승자 발표 화면
    PenaltyRoulette.jsx  꼴찌 벌칙 룰렛
    Confetti.jsx         캔버스 색종이 (의존성 없음)
    TrashTalk.jsx        도발 멘트 배너
  lib/ocr.js           tesseract.js 래퍼, 머리글 확대·대비 보정
  lib/holes.js         홀별 모델, 검산, 홀 단위 통계
  lib/imagePrep.js     OCR 전처리 (확대·그레이스케일·대비·반전)
  lib/cardVision.js    단어 좌표 → 스코어카드 표 복원
  lib/awards.js        우승/꼴찌 집계, 배지, 라이벌 전적, 시즌 랭킹
  lib/trashtalk.js     상황별 도발 멘트 (한글 조사 처리 포함)
```

멤버 이름을 바꾸려면 [`src/lib/handicap.js`](src/lib/handicap.js) 의 `MEMBERS` 와
`MEMBER_COLORS` 를 함께 수정하면 된다.
