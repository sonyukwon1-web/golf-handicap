# ⛳ 낙원 골프

멤버 4명(최진규 · 최문창 · 손유권 · 이지수)의 라운드 스코어를 기록하고,
실제 성적을 기준으로 핸디캡을 자동 산정하는 정적 웹앱입니다.
친구 모임용이라 명예의 전당 · 배지 · 벌칙 룰렛 같은 놀거리를 함께 넣었습니다.

서버가 없고 데이터는 브라우저 `localStorage`에 저장되며, JSON 파일로 내보내고
불러와서 멤버끼리 공유합니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # dist/ 로 정적 빌드
npm run preview  # 빌드 결과 미리보기
```

## 핸디캡 산정 규칙

1. 멤버별로 **최근 5경기의 그로스 평균**을 낸다. 5경기가 안 되면 있는 경기만으로 평균을 낸다.
2. 평균이 가장 낮은 멤버가 **기준(핸디 0)** 이 된다.
3. 나머지 멤버의 핸디 = `반올림(본인 평균 − 최저 평균)`.
4. 넷 스코어 = `그로스 − 핸디`. 라운드 상세에서는 넷 스코어 오름차순으로 순위를 매기며,
   동점은 공동 순위다.

새 라운드를 저장하면 위 계산이 전부 다시 돌아가므로 핸디는 항상 최신이다.

### 과거 라운드에 적용되는 핸디

각 라운드 상세에 찍히는 핸디는 **그 라운드까지의 기록으로 계산한 그 시점의 핸디**다.
지난 결과가 나중 라운드 때문에 뒤바뀌지 않고, 가장 최근 라운드의 핸디는 홈 화면의
현재 핸디와 항상 일치한다.

### 첫 라운드는 그로스로 겨룬다

기록이 한 번뿐이면 그 사람의 "평균"이 곧 그 날 타수라, 핸디가 타수 차이를 그대로
상쇄해 **전원이 동타**가 된다. 우승자도 꼴찌도 안 나오니 벌칙 룰렛도 못 돌린다.
그래서 라운드 순위에 쓰는 핸디는 **본인 기록이 2개 이상일 때부터** 적용한다.
첫 라운드는 그로스 그대로 겨루고, 두 번째 라운드부터 핸디가 붙는다.

(홈 화면에 보이는 현재 핸디는 규칙 그대로 최근 5경기 평균으로 계산한다.)

### 불참 처리

특정 라운드에 빠진 멤버는 타수를 비워두면 된다. 그 라운드의 순위와 평균 계산에서 모두 제외된다.

## 홀별 기록

라운드는 두 가지 방식으로 넣는다. **입력** 탭 위쪽에서 고른다.

- **홀별 기록** — 스코어카드 그대로 18홀을 적는다. 사진 인식도 이쪽으로 들어온다.
- **총 타수만** — 과거 기록을 여러 라운드 몰아 넣을 때 쓴다.

홀별 라운드에 담기는 것:

| 항목 | 설명 |
|---|---|
| 골프장 / 전반·후반 코스 | 예: 리앤리CC, Sky / Lake |
| 날짜 / 티오프 | 티오프는 선택 |
| PAR 18홀 | 각 홀 3·4·5 |
| 플레이어별 18홀 | **파 대비 오버 타수** (0 = 파, -1 = 버디) |

**총 타수는 직접 넣지 않는다.** PAR 합계 + 오버 합계로 자동 계산되고, 표 오른쪽 **T**(그로스)와
**±**(그 9홀 오버 합계) 열에 실시간으로 나온다.

**줄 순서는 카드를 따른다.** 카드마다 이름 순서가 다르므로, 읽어낸 순서를 라운드에 함께
저장하고 입력 표와 상세 표가 모두 그 순서로 그린다.

**칸 값은 치는 동안 글자 그대로 붙들고 있다.** 숫자로만 들고 있으면 `-` 를 치는 순간
숫자가 아니라서 칸이 비워져 **버디·이글을 아예 칠 수 없었다.** 칸에서 손을 뗐을 때만
바깥 값과 맞춘다.

총 타수만 적힌 옛 라운드도 그대로 열린다 (`pars`/`holes`가 `null`이고 총 타수만 표시).

## 스코어카드 사진 인식 (OCR)

사진을 끌어다 놓거나 눌러서 고르면 **Claude 가 읽어** 홀별 기록을 채운다.
**여러 장을 한 번에** 올릴 수 있고, 한 장이 한 라운드다. 한 장을 저장하면 다음 장을 이어서 읽는다.

브라우저에서 직접 부르면 API 키가 노출되므로 서버 함수([`api/ocr.js`](api/ocr.js))를 거친다.
사진은 판독에만 쓰이고 어디에도 저장하지 않는다. 카드 한 장에 약 9초, 65원쯤 든다.

### OCR 은 초안 작성 도구다

읽은 값은 **절대 바로 저장되지 않는다.** 항상 홀별 입력 표에 채워진 상태로 미리보기가 되고,
사용자가 셀 단위로 고친 뒤 "저장"을 눌러야 확정된다.

### 판독에 알려주는 카드 구조

[`api/_scorecard.js`](api/_scorecard.js) 의 프롬프트에 이 앱이 읽는 카드의 구조를 적어 둔다.

- 맨 위 큰 파란 숫자 = 카드를 받은 사람의 총타수, 그 밑이 실명. **표의 첫 줄**이다.
- 요약 카드의 나머지 사람들이 표의 두 번째 줄부터 같은 순서로 이어진다.
- 표는 9홀짜리 두 개. **위가 전반 1~9홀, 아래가 후반 10~18홀** (아래 표의 홀 번호도 1~9 로
  다시 시작하지만 실제로는 10~18번 홀).
- PAR 행의 5 는 파5. 플레이어 칸은 **실제 타수가 아니라 파 대비 오버** (0 = 파, -1 = 버디).
- 버디는 나비·원 같은 그림 안에 적혀 있을 수 있다. 그림에 가려도 부호까지 읽는다.
- T 열은 그 9홀의 그로스 합계다.
- 9홀마다 `PAR 합계 + 오버 합계 == T` 로 검산한다.

출력은 JSON 스키마로 받는다. 길이(18개)는 스키마가 강제하지 못해 프롬프트로 지시하고
서버에서 다시 맞춘다.

### 읽으면 곧바로 표에 들어간다

확인용 목록 화면을 두지 않는다. 판독이 끝나면 알아낸 줄과 라운드 정보(날짜 · 골프장 ·
전후반 코스 · 티오프)가 **바로 아래 표와 입력칸에 들어간다.** 확인은 그 표에서 한다.

### 검산과 되돌리기

각 9홀마다 `PAR 합계 + 오버 합계 == T` 를 확인한다. 어긋나면 미리보기와 입력 표에서
**그 행이 빨갛게** 표시되고 `계산 49 ≠ 카드 47 (+2타)` 처럼 차이를 알려준다.
한 나인에서 못 읽은 칸이 하나뿐이면 `T − PAR 합계 − 나머지 합` 으로 되돌린다.

### 이름 뒤 조사

이름은 자료에서 오므로 문장에 붙여 쓸 수 없다. "최문창가" 처럼 어긋나면 눈에 확 띈다.
[`lib/josa.js`](src/lib/josa.js) 의 `josaWith()` 가 마지막 글자의 받침을 보고 고른다 —
최문창**이**, 최진규**가**. 가려진 이름(`최**`)처럼 한글로 끝나지 않으면 받침 없는 쪽을 쓴다.

### 최씨 두 줄은 팝업으로 묻는다

카드에는 이름이 `이**`, `최**` 처럼 가려져 나온다. 후보가 하나뿐인 줄(카드 주인의 실명,
성이 겹치지 않는 `이**`·`손**`)은 자동으로 확정하고 곧바로 표에 넣는다.

최진규·최문창은 둘 다 `최**` 라 카드만으로는 알 수 없다. **짐작하지 않고 팝업으로 묻는다** —
타수가 같든 다르든 언제나. 잘못 짐작한 값이 조용히 들어가는 것보다 한 번 묻는 편이 낫다.

팝업 맨 위에 **어느 카드인지**(날짜 · 골프장 · 코스 · 티오프) 밝힌다. 여러 장을 이어서
올릴 때 헷갈리기 때문이다. 각 줄에는 총타수와 **전반·후반 홀별 기록**을 함께 띄운다. 총타수가 같아도 홀별은
다르므로, 그걸 봐야 누가 누군지 가릴 수 있다. 한쪽을 고르면 나머지는 저절로 정해지고,
확인을 누르면 그 자리에서 표에 들어간다. "나중에" 를 누르면 그 두 줄만 비워 둔다.

### 휴대폰에서 사진 올리기

- **사진첩은 `<label>` 로 연다.** 숨은 file input 을 코드로 `.click()` 하면 아이폰 사파리가
  막을 때가 있다. label 이 가리키게 두면 브라우저가 스스로 연다.
  input 은 `display:none` 이 아니라 화면에서만 감춘다(`.sr-only`) — 사파리가 그 조건을 본다.
- **EXIF 회전을 반영한다.** 휴대폰 사진에는 회전 정보가 붙는다.
  `createImageBitmap(file, { imageOrientation: 'from-image' })` 를 주지 않으면 눕혀진 채로
  들어와 표를 못 읽는다. 그 옵션을 모르는 브라우저는 `<img>` 로 다시 여는데,
  `<img>` 는 브라우저가 알아서 회전해 준다.
- **HEIC** 도 받는다(`accept` 에 명시). 사파리는 `<img>` 로 열 수 있고, 못 열면
  포맷을 "높은 호환성" 으로 바꾸거나 캡처해서 올리라고 안내한다.

### 판독이 실패할 때

Anthropic 쪽 오류는 그대로 보여주지 않고 무엇을 해야 하는지로 바꿔 말한다 —
크레딧 부족, 요청 몰림, 키 오류, 서버 혼잡. 어느 경우든 표에 직접 입력하면 된다.

### 판독 서버가 없는 곳

미리보기(아티팩트)나 GitHub Pages 처럼 `/api` 가 없는 주소에서는 사진 인식을 쓸 수 없다.
그 경우 그렇게 안내한다. 나머지 기능은 모두 동작한다.

## 화면 상태

보던 탭은 주소에 남는다 (`#rounds`, `#fame`, `#input`). 입력 화면에서 새로고침해도
홈으로 튕기지 않고 그 자리에 머문다. 뒤로 가기도 탭 이동으로 동작한다.

## 같은 카드를 두 번 넣지 않는다

**날짜가 같고 네 명의 타수가 모두 같으면** 같은 라운드로 보고 저장을 막는다.
골프장 이름은 인식이 조금씩 달라질 수 있어 판단에 쓰지 않는다.

막혔을 때 폼을 비우지 않는다 — 실수로 날아간 것이 아님을 알 수 있어야 한다.
여러 장을 한 번에 넣어 일부만 중복이면 나머지는 저장하고 몇 개가 걸렸는지 알린다.

## 데이터 공유

- **내보내기** — 전체 기록을 `낙원골프_YYYY-MM-DD.json` 파일로 저장한다.
- **불러오기** — 받은 JSON 파일을 열면 현재 기록을 그 파일 내용으로 대체한다(덮어쓰기 전 확인창이 뜬다).

기록을 관리하는 사람이 라운드를 입력하고 파일을 단톡방에 올리는 식이 가장 단순하다.

## 배포

### GitHub Pages

저장소 **Settings → Pages → Source** 를 `GitHub Actions` 로 바꾸고 `main` 에 푸시하면
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) 이 알아서 빌드·배포한다.

### Vercel (권장 — 사진 인식이 여기서만 된다)

저장소를 import 하면 Vite 프로젝트로 자동 인식되고 `api/` 아래 함수가 함께 배포된다.
**Settings → Environment Variables 에 `ANTHROPIC_API_KEY` 를 넣어야** 사진 인식이 동작한다.

로컬에서 API 까지 함께 띄우려면 `vercel dev` 를 쓴다 (`.env.local` 에 키를 둔다).
`npm run dev` 는 앱만 띄우므로 사진 인식이 동작하지 않는다.

`vite.config.js` 의 `base: './'` 덕분에 루트 도메인이든 `/<저장소이름>/` 하위 경로든
그대로 동작한다.
